# Test-Driven Development (TDD) Rule

## 必須事項
本ワークスペース（`games`）において新規機能の実装、既存機能の拡張、またはバグ修正を行う際は、**必ずテスト駆動開発（TDD）を適用してください**。

### TDD 開発フローの厳守
1. **RED（失敗するテストの作成）**:
   * 要件や修正対象のバグを再現・検証するテストコードを `tests/` 配下に作成する。
   * テストを実行し、意図通りテストが失敗（RED）することを確認する。
2. **GREEN（実装とテスト通過）**:
   * テストを通過させる最小限かつ堅牢な実装・修正を行う。
   * テストを実行し、全テストケースが合格（GREEN）することを確認する。
3. **REFACTOR（リファクタリングと再検証）**:
   * コードの可読性・保守性・安全性を向上させ、テストが再度GREENであることを確認する。
4. **コミット・デプロイ前の全件検証**:
   * `npm test` が100%成功していることを確認せずにコミットやデプロイを行ってはならない。
